# 52-week highs

The module starts from the selected **completed** New York session. It measures the high of that session (not the close) against the maximum of its prior trading sessions within a trailing window of exactly 52 × 7 calendar days including the selected session. Equal highs qualify and are labeled separately from new highs. The filter is **strictly more than 5,000,000 shares** reported for the selected session, independent of other scanners. Results are historical, not intra-session or live.

The API uses Massive SPY daily candles to validate the session list, then checks existing Neon grouped-day coverage. If any expected date is missing, it reports pending coverage with no asserted 52-week highs, not “zero hits.” The market-wide records are US listed instruments excluding OTC; the available cached security type excludes known non-common instruments. Unknown identifiers are marked as such and the current cached classification is not a point-in-time certification. Symbols without an observation at the start are conservatively omitted; the endpoint does not attempt to link ticker changes. The SQL checks the volume gate before aggregating prior highs and only returns a shortlist, not market-wide raw candles.

Historical candles in the shared cache were fetched with split adjustment enabled by the existing scanner; stale bars may have been cached before a split. A successful current market-wide Massive split feed is therefore required. The module excludes symbols whose split occurred at or after the oldest cache refresh or after the selected volume date. That date-level guard is intentionally conservative. The online API never backfills; its external queries are market-wide, not per instrument.

## Operator-only coverage setup

With approval to write to the intended Neon environment and already configured server credentials, run `node scripts/backfill-52w.js YYYY-MM-DD 3` only from an operator environment. It adds at most five missing sessions per invocation and waits between grouped API requests. This can take many bounded batches from an empty cache: it is not an automatic initial population, not run as part of deployment, and does not assume paid Massive access. Do not run concurrent backfills or schedule one before approving provider quota and DB storage/compute. From Basic, consult [Massive's daily data availability](https://massive.com/knowledge-base/article/on-the-free-basic-plan-when-can-i-pull-the-previous-trading-days-data); other scanner routes may share its quota.
